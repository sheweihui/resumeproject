## 2. 测试目标

- 验证秒杀接口在高并发下不会超卖。
- 验证同一用户重复请求会被幂等拦截。
- 验证限流策略在高频请求下生效。
- 观察 QPS、平均响应时间、P95、失败率。

## 6. 现象分析

填写示例：

- 当并发逐步提升到 500 VU 时，部分请求被限流拦截，接口没有出现 5xx 大面积错误。
- Redis 库存没有扣成负数，MySQL 最终库存与订单数量一致。
- 同一用户重复请求时，SETNX 幂等标记生效，后续请求被拦截。

## 7. 后续优化

- 增加更多测试用户，避免单用户幂等影响压测真实性。
- 使用分布式压测或云服务器压测，减少本机瓶颈干扰。
- 增加 MQ 消费端监控，观察异步任务堆积情况。
- 增加 Grafana / Prometheus 监控接口耗时、Redis 命中率和 MQ 堆积量。
